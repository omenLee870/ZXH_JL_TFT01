# 优仪宝（天津宗申三轮）一线通

当前工程选用 **PC05 / `IO_PORTC_05`**，默认上电启动控制器到 TFT 的单向接收。用硬件 GPTIMER 双边沿捕获，空闲时内部下拉，约每 100ms 在 LVGL 线程更新界面。

## 引脚与接线

当前启用的是 JL380N、MIPI JD9165T 屏和 DVP group C 摄像头。PC05 在 RGB 软 SPI 屏和 DVP group B/D 配置中出现，但这些配置当前未启用；SD1、CAN、触摸、摄像头 group C、当前 SPI2 和调试串口均不使用 PC05。切换屏接口或摄像头组别时需重新核对。

软件配置不能证明 PCB 上 PC05 已引出或没有外部负载，接线时应对照实际原理图/焊盘。协议仅写 TTL，未指定实际高电平电压：控制器信号经过接收保护/电平转换后，向 PC05 提供 **0~3.3V、非反相、空闲低电平** 信号，并连接信号参考地。5V 或车载高电压线路不能直接接 GPIO。

## 协议实现

来源：`D:\众鑫汇\omenLee的项目\TestBox\一线通发码盒要求和协议\优仪宝通信协议（天津宗申三轮）.pdf`。

- 完整帧为同步脉冲加 DATA0..DATA11，即 12 字节/96 数据位；文档第 1 页“65 bit”与第 4 页完整表格冲突，以完整表格为准。
- DATA0=`0x59`，DATA1=`0x42`，DATA11 为 DATA0..DATA10 异或。
- 每位先低后高，直接比较该位的实际脉宽：高电平长于低电平判 1，低电平长于高电平判 0；相等或任一脉宽为 0 则丢弃该帧。协议的标称比例为 0 低 2T、高 T，1 低 T、高 2T。同步为低电平大于 20ms 且大于 31T，再高 T。
- 自动检测字节内 MSB/LSB 位序，也可以通过配置接口固定。文档没有明确字节内位序。
- 文档的 Tosc 范围与建议 T 不一致，因此接收同步高脉冲范围为 350~11000us；推荐发码短脉冲 500us。同步高脉宽仅用于识别同步、诊断和超时，不作为数据位的固定脉宽门限。数据判位不要求精确的 1:2 比例，也不使用原来的 25%+40us 容差。
- 默认有效帧超时 1000ms；慢速波形按帧长度放大超时。错帧不更新业务状态，不延长有效帧超时。掉线后速度/电量标为未知，并清除过期状态。
- DATA6 的负电流默认按符号位加 7 位幅值解释；文档只明确最高位为符号位，没有明确负数编码，可通过配置接口切换补码。保留原始字节便于核对。

解析全部 22 个有效状态位：驻车、侧撑、霍尔故障、转把故障、控制器故障、欠压、巡航、助力、缺相、运行、刹车、其它保护、滑行充电、防飞车、70% 电流标志、一键通、EKK、过流、堵转、倒车、电子刹车、限速。档位为 DATA4 低两位加最高位的 4，范围 0..7。DATA9/10 作为电量/负载百分比，超过 100 时标记无效。

## 速度与本地里程

参考：`D:\众鑫汇\omenLee的项目\ZXH-YBOFR2\ZXH-YBOFR2(20260427)\Projects\PY32F002B-STK\Example_LL\ADC\ADC_VrefintAndVrefbuf_Init\Src\YXT.c`，对应 `Inc\APP.h` 的 `C_YXT_SPEED=17`。

默认与参考程序一致：

```c
hall = (DATA7 << 8) | DATA8;
speed_kph = hall / 17; // 整数截断
// 原工程的可调除数：17 + R_YXT_SPEED_SET - 9，原设置范围 0..18。
```

除数可通过 `youyibao_sif_save_config()` 配置接口修改，原程序常用范围为 8..26，初始值为 17。也保留可选的物理参数：同时配置轮胎周长 C（mm）与包含减速比的每轮三路霍尔变化总数 N 后，使用 `speed_dkph = hall * C * 72 / (N * 1000)`；任一物理参数为 0 时使用除数法。

总里程/小计里程由有效车速按真实毫秒间隔积分，保留不足 1mm 的余数；掉线后不再累计，不按照“收到一次报文就加一段距离”。总里程是本机估算值，首次从 0 开始，不包含旧仪表历史里程。小计可调用 `youyibao_sif_reset_trip()` 清零。

设置存储在 VM ID 59，总里程在 VM ID 58，均已在 `user_cfg_id.h` 预留。停车/掉线时保存，停车保存间隔至少 30 秒，离线时最多每 5 分钟尝试保存；行驶中突然断电会丢失上次保存后的估算里程。小计不跨重启保存。

## 界面

传统仪表页和宠物仪表页都显示真实车速、电量、档位、故障和本地总里程。宠物页还显示刹车图标，小狗动画使用真实车速。多故障每 1.5 秒轮播英文名称；这些名称不是厂家故障码。根据用户要求，页面已移除 `SIF ON/OFF | 电流` 按钮及其诊断面板。接收、解析及业务更新继续运行，已有 VM 校准值继续使用，诊断使用 PA12 串口日志。

倒车状态由无到有时，若当前正在传统/宠物仪表页，会进入现有摄像头页并启用已有倒车语音；倒车解除或通信掉线后返回原仪表。用户主动离开自动倒车页后，同一次倒车不会强行重新打开；升级页面不被切走。

协议没有下发灯光、温度、天气、READY、锁车或控制命令，因此不把这些信号伪造成真实反馈，也不通过一线通向控制器发控制命令。

## 验证与上板检查

运行：`powershell -NoProfile -ExecutionPolicy Bypass -File tools/TestYouyibaoSif.ps1`。

协议测试覆盖逐位状态映射、档位、电流、速度参考算法、两种位序、500~10000us 波形、抖动、PC05 实测波形片段、原发码盒相位/换字节偏差、高低脉宽仅差 1us、相等/零脉宽、错误帧、丢边沿重同步、计时回绕、掉线和里程积分。UI 测试使用实际 LVGL 控件，替代硬件数据源和摄像头/语音出口，验证数据显示、倒车生命周期、掉线、升级和页面删除。目标工程用杰理工具链编译并链接，未自动烧录。

上板时确认 PC05 输入幅值与极性，发 `59 42 ... XOR` 报文并观察串口在线状态、同步脉宽和错误计数，再检查速度、P/R/刹车/故障以及断线回退。核对除数 17 的速度与实车测速；如旧板已有校准值，填入 `17 + 旧校准值 - 9`。

## 串口定位未解码

PA12 是调试日志 TX，波特率 1000000、8N1；PC05 是一线通信号输入。当前版本启动日志为 `diag=3 bit=H>L`，每 2 秒输出一次 `[YYB_DIAG]`，不在捕获中断中打印。`diag=2` 是使用固定脉宽容差的旧诊断版本。

- `edge/rise/fall` 是累计捕获次数；持续为 0 时检查信号是否到达 PC05、参考地、电平及引脚配置。
- `repeat` 是连续捕获读到相同电平的次数，持续增加时检查漏边沿、中断延迟或波形毛刺。
- `T` 是同步高脉宽，`bits/active` 是解码进度，`timing/head/xor` 分别为时序、帧头和校验错误累计次数。
- `[YYB_WAVE]` 的 `L/H` 表示刚结束区间的电平，数字单位为微秒；保存最近长区间及其后最多 19 个区间。无长区间时保留启动后的样本。
- `good` 增加时输出 `[YYB_RAW]`，包含最近有效的 12 字节和解析状态。即使不显示日志，界面仍每 100ms 更新。

2026-10-15 对 TestBox_project 的 `yxt_protocol.c` 原发送代码按原中断调用顺序（先 `YXT_Interrupt`、再 `YXT_Task_Process`，每 100us 一次）做主机回放：实际开头为 `L40000 H600 L900 H600 L400 H1100 ...`，旧解码器结果 `T=600 good=0 timing=1`。发送状态机切换 phase 时未同时翻转输出，下一次中断才改变 IO；`YXT_NEXT_BYTE` 还增加字节边界的时序偏差。旧解码器把同步高电平直接当作精确 T，数据低 400us 超出允许范围（410..790us），因此首字节即失步。随后 PC05 实板日志确认了同类波形（例如 `L55304 H591 L891 H601 L394 H1097 ...`）。

当前根据用户要求改为逐位比较实际高低脉宽，保留同步、96 位长度、帧头和异或校验。未修改的原发码盒发送代码完整回放结果为 `T=600 good=1 timing=0 header=0 xor=0`，无需为此修改发码盒。实测日志只保存了每帧开头的有限脉宽，因此实测片段回放只验证首字节和持续同步状态，完整帧使用原发码盒发送代码回放验证；仍需更新仪表固件后进行实板联调。

此前准备的 `output/youyibao-testbox-replay/testbox_yxt_timing_proposed.patch` 仅是发码盒恢复标称时序的可选补丁，未应用到 TestBox 原工程。该补丁不再是一线通联调的前置要求。
