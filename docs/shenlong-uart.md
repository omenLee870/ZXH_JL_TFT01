# 神龙锂电2号串口版与车辆模拟上位机

当前版本v3.6：神龙遥测保持14字节，灯光/倒车/档位/充电/骑行模式使用版本3独立AT测试通道。上位机和固件配套升级。测试与未来物理输入共用统一车辆状态，物理输入逐字段优先，测试1.5秒未续期自动释放。短时UI停更仅暂停续期，不主动清除倒车/档位。命令、确认、退出及物理接口见[vehicle-test-control.md](vehicle-test-control.md)。v3.3的18字节灯光扩展仅保留兼容旧软件。

## 构建与入口

默认板级选择为 `TCFG_SHENLONG_UART_ENABLE=1`，一线通代码保留，设为0恢复一线通。PC04是UART1 TX，PC05是RX；原PA12 UART0调试日志继续使用1000000波特率。PC04对应的NTC默认关闭，当前摄像头为DVP group C；改变板级外设配置后需要重新检查引脚冲突。代码配置不能确认PCB焊盘引出情况。

运行 `tools/BuildShenlongFirmware.ps1` 仅编译和链接 `SDK/cpu/br33/tools/sdk.elf`，不会执行SDK的下载脚本。`-OneWire`切回一线通编译；脚本在切换编译参数时更新板级头文件时间，避免复用上一协议的目标文件。当前桌面程序源码位于旁边 `D:\omenLee_project\ZXH-TFT\380tft_1\上位机`，运行和打包步骤见该目录README；`desktop/vehicle_simulator`仅为旧版存档。

## 数据流

```text
上位机车辆模拟 → 14~25字节控制器反馈 → UART1 RX → sl_decoder
    → vehicle_controller → app_vehicle → 普通/宠物仪表UI

仪表本机灯光/模式/电源状态 → 20字节仪表命令 → UART1 TX
    → 上位机解析 → 车辆灯光/动力/参数视图

上位机AT测试命令 → UART1分流 → 测试输入槽 ─┐
未来物理适配 → app_vehicle_aux_publish ─────┼→ 统一快照 → 仪表业务/UI
原协议已知状态 ────────────────────────────┘
```

电脑固定9600、8N2、无流控，默认120ms发送一次。仪表端SDK没有停止位参数，使用UART1的恒1校验模式8M1，使数据8位之后连续两个高位，线上等效8N2。SDK头文件注明UART v1不支持校验配置，因此不能未经确认移植到v1。当前BR33头文件提供独立TX/RX控制寄存器和恒1枚举；仍需在实际板子用逻辑分析仪检查位宽约104.17us及两个停止位。

## 反馈帧（电脑→仪表）

| 字节偏移 | 含义 | 实现 |
| --- | --- | --- |
| 0~2 | 地址、总长、命令 | 02、实际帧长、01 |
| 3 | 状态1 | 6km/普通巡航、霍尔/转把/控制器/欠压/缺相 |
| 4 | 状态2 | 刹车、通讯故障、bit3充电映射到统一状态；水平/PAS等原始位保留在raw |
| 5~6 | 电流，大端 | bit14为0.1A单位标志；其余低14位为幅值 |
| 7 | 电流比例 | 0~100有效，超界不作为负载显示 |
| 8~9 | 一轮周时间，大端ms | 轮径×π÷周期换算车速；0未知、≥4000停止 |
| 10 | 电量 | 1~100有效；0因无BMS歧义保守显示未知 |
| 11~12 | 剩余里程，大端km | 保留在decoder中，现有仪表UI没有对应控件 |
| 最后 | XOR | 全帧异或为0，扩展帧校验始终取最后字节 |

有效报文1秒超时；无效报文不更新在线时间。解析支持14~25字节、分块/连续帧、噪声后重同步。MCU每10ms读取DMA环形缓冲，不依赖USB读取块或固定14字节边界。残帧在30ms以上读数据间隔后丢弃；正常完整帧仍检查地址、长度、命令与XOR。接收空闲阈值15ms。

轮径默认16.0英寸，速度使用0.1km/h单位并四舍五入；轮径与上位机不同会导致车速不一致。4000ms停止阈值意味着16英寸轮径最低非零可表示速度约1.15km/h。里程按新鲜车速及真实时间积分，超时停止累计，复用现有双记录总里程存储与停车保存策略；小计不跨重启保存。

原协议没有电压、真实档位、钥匙、大灯或倒车反馈字段。PAS故障位1也可能表示不支持，保留原始值，不直接作为确定故障显示。电流最高bit15负数含义未定义，置位帧拒绝接收。

### ZXH灯光扩展（v3.3，diag=3）

旧v3.3上位机勾选“ZXH灯光联动”时发送18字节帧；当前v3.4上位机固定发送14字节遥测，额外操作改用独立AT通道。下述旧扩展只为兼容v3.3保留，不占用原状态保留位。

| 字节偏移 | 内容 |
| --- | --- |
| 0~12 | 原反馈字段，偏移1总长改为18 |
| 13~15 | 5A 58 01（ZX，版本1） |
| 16 | bit0大灯、bit1示廓灯、bit2左转、bit3右转；高四位必须为0 |
| 17 | 全帧XOR校验 |

解析到标识、版本及灯位均有效时，反馈实际供电灯状态，宠物仪表显示四种灯，左右转向按500ms亮/灭显示；普通仪表页显示左右转向。14字节帧或未知扩展清除扩展灯状态，不影响基础遥测接收。大灯扩展有效时以反馈为准，否则沿用仪表本机灯光状态。上位机手动大灯操作优先于跟随，再次勾选跟随恢复仪表控制。此扩展不能用于推断原厂控制器是否支持这些灯。

模拟器驱动模式按0纯助力、1纯电、2助力＋电驱分别执行；模式2允许脚踏或转把单独起步，两者同时输入取较大动力比例。仅明确设置非零启动时限制静止电驱，未修改仪表默认模式2。

宠物仪表的四个信号柱恢复显示，保留中性色。当前没有接入真实RSSI，因此不表示实时网络强度。启动标识为`diag=3 tx_idle_positive lamps=ZX1`，包含下述首帧发送修复。

### 时间、日期与天气显示保留

时间优先使用合法RTC，缺少历史校时标记不再导致整块空白。RTC不可用时继承已保存的校时时间并继续走时；从未保存时使用编译日期时间作为显示默认值。后两种只是显示回退，维持未校准标志，时钟用较淡颜色；手机BLE校时或本机时间设置保存成功后恢复正常亮度。日期与星期按相同时间计算，串口掉线不清除时间。

天气有效期仍为两小时，但过期只取消实时标志，继续显示最近天气和温度。切页沿用内存状态，重启读取带校验的天气缓存；缓存最多每小时写入一次，升级期间不写，短时间内的新结果先保留在内存。首次无缓存默认显示多云、25°C。缓存和默认天气以较淡颜色显示，收到有效手机天气后恢复正常亮度；未知天气消息不覆盖上次有意义的结果。默认值不是实测天气，串口车辆协议也不携带天气信息。

## 仪表命令（仪表→电脑）

仪表发送20字节帧，地址01、命令01。驱动模式2、默认助力10；本机ECO/CITY/SPORT对应5/10/15。大灯和控制器工作位来自`app_meter_control_snapshot`，快照暂忙或尚未就绪时不发送默认开机命令。转把PWM默认0，不主动给硬件转把命令。其余参数为当前台架默认值：46片测速磁钢、轮径16英寸、灵敏度12、启动强度1、限速60、限流20A、欠压42.0V、8颗助力盘磁钢。这些默认值用于模拟联调，尚未提供全部参数的仪表设置界面。

上位机兼容20~25字节命令，也识别21字节版本的助力PWM。PDF的21字节表格沿用帧长20，实际必须写21；驱动方式表格1~3与正文0~2冲突，采用正文0~2。参数页保留可观察字段；车辆运动为简化模型，没有模拟全部助力控制算法。

## 2026-10-19 首帧发送修复（diag=2）

实板日志显示控制器反馈持续被正确接收（online=1、rx从17增至130），但仪表tx和txerr一直为0。检查实际链接的BR33 uart_v3驱动可见：uart_init将发送状态初始化为2；uart_is_send_complete直接返回该状态；DMA发送时为0，发送完成中断后为1。SDK头文件只列出0/1，原适配代码严格判断等于1，导致第一帧永远无法开始发送。

现改为仅在返回值大于0时发送：同时接受首次空闲2与发送完成1，忙0和负数错误均不改写TX DMA缓冲。仍须取得有效仪表状态快照，快照未就绪时不会用默认开机值发帧。启动日志增加`diag=2 tx_idle_positive`，周期日志追加`txstate`、`snapshot`、`skip`，用于区分驱动忙/错误与仪表状态未就绪。回归测试覆盖首次空闲2、忙0、完成1、负数错误和关机重开后的首帧。

核验方式：烧录修复包后保持USB TX→PC05、USB RX→PC04和共地，打开上位机及软件钥匙，PA12周期日志中的tx应递增，上位机RX也应递增。软件测试和编译通过不等于已完成这次实板回归。err是累计值；若启动后停止增加，不能仅凭该累计数认定持续通信故障。

## 电源与未接通部分

软件钥匙只控制模拟车辆状态和上位机发帧，不控制仪表物理电源。真实仪表逻辑关机沿用现有电源生命周期，会停止UART并保存里程；此时不能靠该UART唤醒，继续使用现有BLE开机或硬件供电方式。

当前v3.6左右转向、示廓灯、倒车、档位、充电和骑行模式通过独立AT测试通道进入统一状态。倒车测试使用既有切入视频页/自动返回流程，测试释放或超时后退出；不改写原神龙反馈的保留位。实车物理入口已预留，GPIO、检测电路及灯具输出驱动尚未绑定，不能把测试确认当作真实灯线回读。电源、时间和天气继续使用原业务入口；骑行模式通过AT测试状态同步，退出后恢复本机模式。
