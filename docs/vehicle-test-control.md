# 车辆统一输入与独立测试命令（v3.6）

测试台架和后续实车使用同一车辆状态及业务/UI流程。原协议负责其定义的遥测，测试命令作为独立输入来源；物理适配不依赖测试命令，更不依赖“上位机动画”。

```text
神龙遥测 ─────────────────────┐
AT测试控制 → 测试输入槽 ───────┼→ 统一车辆快照 → 图标/档位/倒车页面/其他业务
物理采样/实车报文 → 物理输入槽 ┘
```

优先级逐字段为：有效物理输入 > 有效测试注入 > 原协议状态。known字段包含“明确关闭”，不是只有打开才算有效。独立输入不会伪造控制器在线、车速、运动状态或里程。测试租约过期后，重新使用有效物理或协议来源。

## 串口与命令

共用现有UART1，TX PC04、RX PC05，9600/8N2。原神龙控制器反馈保持14字节，仪表命令保持20字节。ASCII命令以CRLF结束（也接受LF），二进制帧与ASCII按完整帧分流，二进制载荷内的ASCII字符不会作为命令执行。PA12继续只用于日志。

请求编号1~65535，超过后循环；同一未完成请求可重发，相同编号和内容返回缓存确认，不重复执行或延长租约。同编号不同内容返回ERROR,4。上位机只确认当前请求编号对应的结果，旧回包不能确认新操作。

| 命令 | 用途 |
| --- | --- |
| `AT+ZXHGET=编号` | 查询版本与当前合并状态，供握手使用 |
| `AT+ZXHSET=编号,flags,gear,mode` | 原子更新本次测试灯光、倒车、充电、档位和骑行模式，租约1500ms |
| `AT+ZXHCLEAR=编号` | 释放测试来源；物理及原协议来源不清除 |

flags的有效值为十进制0~31或64~95：bit0大灯、bit1示廓灯、bit2左转、bit3右转、bit4倒车、bit6充电。flags bit5保留，置位将被拒绝。一次SET明确提供全部六个开/关状态。gear是0~15，255表示不提供测试档位；上位机采用已匹配档制的显示档位，不把助力原始等级猜成档位。

```text
AT+ZXHGET=1
AT+ZXHSET=2,4,2       左转开启，其他四个状态关闭，测试档位2
AT+ZXHSET=3,12,2      左右转同时开启（双闪）
AT+ZXHSET=4,16,2      倒车，使用现有倒车切页/返回流程
AT+ZXHCLEAR=5         退出测试，释放所有测试字段
AT+ZXHSET=6,64,255    充电，其他五个状态关闭，不注入档位
AT+ZXHSET=7,76,2      充电加双闪，测试档位2
```

以上行尾实际发送CRLF，不发送中文注释。

## 回包与确认边界

```text
+ZXH:编号,OK,3,flags,gear,known,physical,mode
+ZXH:编号,ERROR,错误码
```

成功回包中的3是命令通道版本。v3.6上位机只确认版本3，需与v3.6固件配套升级。flags/gear为合并后的当前状态，可能被有效物理输入覆盖。known/physical为0~255十进制位图：低五位和bit6同flags，bit5表示档位已知/来自物理来源，bit7表示骑行模式已知/来自物理来源。完整SET带档位、模式时known=255；不提供模式时为127。未知档位为255。没有物理来源时physical为0。

错误码：1语法/编号错误；2参数越界；3状态服务未就绪或暂忙；4同编号内容冲突。无效请求不更新输入。回包队列最多4项，队列满时不执行无法确认的新命令，上位机超时重试。

OK确认的是共享业务状态已经接收并可查询，不是灯线电压或执行器回读。上位机显示“测试状态已确认”；若physical非0，提示“物理输入优先”。无匹配确认时显示等待、拒绝或超时，不能把本地动画亮起当作仪表执行完成。

当前命令支持灯光、倒车、档位、充电和骑行模式。原协议状态2 bit3也映射到VEHICLE_CHARGING；测试明确关闭时覆盖该字段，物理检测逐字段优先。宠物及普通仪表在电池区域右侧显示单个闪电，无底框和CHG文字，SOC保持独立，能量回收不等于充电。BLE BMS查询同一合并充电状态，未知时仍为-1。电源生命周期、时间和天气继续使用原有业务入口；尚未提供对应AT写命令。后续增加命令必须接入对应业务服务及完成反馈，不能直接操作LVGL控件。

## 退出、掉线与生命周期

- 上位机先GET握手，再SET；测试开启且模拟钥匙上电时每400ms刷新租约。
- 模拟下电、暂停发送、关闭测试控制时发送CLEAR；正常断开尝试发送CLEAR。
- UI超过300ms不更新时串口线程仅暂停续期，不主动CLEAR；避免短时界面卡顿造成CLEAR/SET交替，引起倒车反复切页及档位闪烁。串口断开或程序异常时，仪表端1500ms租约到期后自动释放。
- 逻辑关机会清除输入槽，不继承上一个电源周期的测试或物理采样。恢复后适配层重新发布。
- 一线通编译也保留统一物理输入接口；AT传输当前仅接到串口版UART1，不会额外占用一组IO。

## 后续物理适配接口

`SDK/apps/watch/common/app_vehicle.h`：

```c
int app_vehicle_aux_publish(enum vehicle_aux_source source,
    uint32_t known, uint32_t status, int gear, uint32_t timeout_ms);
```

物理来源使用`VEHICLE_AUX_PHYSICAL`，known/status采用`vehicle_status`的统一位定义（不是AT的紧凑flags），gear=-1表示不提供档位。timeout_ms为1~60000毫秒，必须按采样周期持续刷新；0释放该来源。接口校验来源、支持位及参数范围。

```c
/* 在app_core执行：示例为物理灯光输入，不猜测具体GPIO。 */
uint32_t known = VEHICLE_HEADLIGHT | VEHICLE_POSITION_LIGHT |
                 VEHICLE_LEFT_TURN | VEHICLE_RIGHT_TURN;
uint32_t active = /* 由检测电路/报文适配得到的统一状态位 */ 0;
app_vehicle_aux_publish(VEHICLE_AUX_PHYSICAL, known, active, -1, 1000);
/* 同一物理槽若负责充电，须将充电与其余已采样字段一起发布。 */
known |= VEHICLE_CHARGING;
active |= VEHICLE_CHARGING; /* 检测为充电；检测未充电时清除此位 */
app_vehicle_aux_publish(VEHICLE_AUX_PHYSICAL, known, active, -1, 1000);
```

所有输入在app_core串行处理；GPIO中断或其他线程先投递app_core，不能在ISR/UI直接调用。快照使用已有信号量保护，UI只读取副本。

当前用户尚未确定物理接法，因此未绑定GPIO、电平检测、消抖或灯具输出驱动。以后确定接线后，只需要实现物理适配并发布到这个入口，再做实板验证；已有图标、优先级和倒车业务可共用。不能据此宣称尚未接线的真实灯具已经可被控制。

## v3.6 骑行模式

SET第四参数mode=0 ECO、1 CITY、2 SPORT、255不提供；为兼容手工命令也接受旧三参数SET（不注入模式）。例：`AT+ZXHSET=200,64,2,0`为充电、档位2、ECO。回包末尾返回当前合并模式，未知为255；known/physical bit7对应模式。模式与灯光/档位共用1500ms租约，退出测试恢复本机模式。

统一物理入口采用 `known=VEHICLE_RIDE_MODE_MASK`，status单选 `VEHICLE_MODE_ECO` / `VEHICLE_MODE_CITY` / `VEHICLE_MODE_SPORT`，可以与其他已采样字段合并发布；不接受不完整模式掩码或多模式同时置位。物理模式逐字段优先。

UI文字、颜色、普通仪表模式文字、BLE模式查询及串口返回等级均采用当前合并模式。上位机按钮原来仅修改本地速度预设，本版将模式加入实际发送载荷。新增96组模式/灯位跨语言对照和真实LVGL模式/充电位置回归；不把模式注入当作永久保存本机设置。
