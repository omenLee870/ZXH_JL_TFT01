# 仪表蓝牙音乐逻辑

业务实现：`SDK/apps/watch/common/pet_dashboard_music.c/.h`。

- `app_main.c` 在 `app_core` 初始化检测服务，100 ms 查询一次经典蓝牙连接和 A2DP 状态。
- 应用层处理播放进入、暂停 3 秒退出、手动切换和 AVRCP 控制。
- UI 点击通过 `APP_MSG_PET_DASHBOARD_MUSIC` 投递给应用线程，不直接修改业务状态。
- 应用层仅在状态变化或页面请求刷新时发送快照；UI 适配通过 LVGL RPC 显示。
- `custom/chongwuyibiao_yinyue.c` 只绑定控件、转交点击和更新显示，不读取蓝牙或计时。
- 页面重建不重置业务状态；主界面动画在音乐区显示期间停止，返回时恢复。
- 蓝牙歌曲回调限长复制后投递 `app_core`，文本不保留协议栈临时指针。
- 连接/开始播放时补取歌曲信息，播放期间每 2 秒补取；封面按 AVRCP type=8 的七位句柄去重。
- 歌名和歌词使用完整 TTF 动态取字，避免仅生成静态示例字形。
- `chongwuyibiao_yinyue_donghua.c` 只负责视觉动画：唱片 18 秒一周，两个音符各 1.1 秒交替上飘并淡出。

工具的独立预览没有应用任务或真实蓝牙。下面的联动测试会连接同一应用状态机与真实 LVGL 控件。

## 自动验证

在工程根目录执行：

```powershell
& ./SDK/apps/watch/common/tests/run_pet_dashboard_music_tests.ps1
```

可用 `-Compiler '路径/gcc.exe'` 指定工具附带的 32 位 MinGW。

覆盖：3 秒边界、快速恢复、手动返回不抢占、断开/重连、时钟回绕、通知失败重试、页面删除重建、非零结尾蓝牙文本、UTF-8 截断、换歌清理、封面拷贝、唱片暂停恢复、音符交替及淡出。

## 手机联调

固件代码和新 UI 资源必须配套更新，不能只烧固件而沿用旧图片编号。

|操作|预期|
|---|---|
|未连接启动|原小狗和草地，隐藏蓝牙图标|
|手机连接，并把媒体输出选成本机|显示蓝牙图标，保持主界面|
|手机开始播放|显示音乐区和暂停按钮|
|手机发送歌曲属性|歌词模式中，ARTIST 完整的歌曲/歌手文字显示在上方，TITLE 显示在歌词区|
|同一首歌逐句更新 TITLE|只更新歌词，不改变歌曲标识、不清封面、不重置唱片角度|
|ARTIST 先返回歌手、再补全歌曲信息|只更新文字，不失效封面、不重置旋转、不重复取图|
|type=8 封面句柄改变|切回默认唱片，获取新封面；传输中换封面由 SDK 在旧 STOP 后续取|
|手机发送 BIP 封面|圆形裁剪并替换默认 die 唱片，播放时旋转|
|手机未发送封面或取图失败|继续使用 die 默认唱片，不沿用上一首封面|
|手机播放、暂停或手动返回|音符交替上飘淡出；暂停、隐藏或退出页面时停止|
|手机暂停|显示播放按钮；持续暂停 3 秒后回主界面|
|暂停不足 3 秒后恢复|保持音乐区，不闪回主界面|
|播放时点击耳机小狗|回主界面，手机继续播放，持续播放不再自动跳回|
|点击主界面小狗|重新显示音乐区|
|手动返回后暂停再恢复|自动进入音乐区|
|点击上一曲、下一曲、播放或暂停|向手机发送对应 AVRCP 命令；以实际蓝牙反馈更新按钮|
|断开蓝牙|回主界面，隐藏蓝牙图标|

当前识别的是 A2DP 媒体音频流，视频声音也可能进入音乐区。

2026-10-08 实机日志已确认开启手机蓝牙歌词后的格式：TITLE(type=1) 是当前歌词行，ARTIST(type=2) 是歌曲与歌手组合。同首歌的 TITLE 逐句变化而 ARTIST 保持不变。本版明确按此格式映射，不按 App 名称分支，不根据文字长短、变化频率或时长猜歌词。

`pet_dashboard_music.h` 的 `PET_DASHBOARD_BT_LYRICS_MODE` 默认是 `1`（本轮验证的歌词模式）：TITLE→歌词、ARTIST 原文→上方歌曲信息。设为 `0` 并重新编译可使用普通歌曲模式：TITLE→歌名、ARTIST→歌手。配置必须与手机发送格式相符；本版没有自动切换模式或新增设置控件。

歌曲信息保留完整原文，不猜分隔符。TYPE1→TYPE2 顺序中缓存本组歌词，歌曲信息随后改变时仍保留新歌首句；若新歌曲信息先到且没有本组歌词，则清空旧歌词等待新行。TITLE-only 更新立即显示，重复文本不重复发 UI 快照。`0x80` 额外歌词入口保留，现有 screen_trans 私有耳机链路不接入。

2026-10-08 后续实机日志确认：ARTIST 可能先发歌手，再补成歌曲/歌手组合；数字 `0000052` 等来自 AVRCP type=8 封面句柄。SDK 的元素属性解析器会先将 type=8 交给歌曲信息回调，再交给 BIP。封面现在以该句柄去重，不以 ARTIST 文本判断。同一封面句柄不代表同一歌曲；共用封面的歌曲可以保留图片和旋转，文字独立更新。

接收服务同步记录选中句柄、当前请求句柄和缓存句柄。请求投递后就记录 pending，避免尚未收到 START 时被重复请求；连续切歌也不会把旧传输标成新封面。SDK 在 STOP 后自动续取不同的新句柄。重复请求状态 5 不清缓存；状态 6 在等待/接收期间保留数据；真实错误 4 才释放缓冲。图片解码后仍核对句柄，状态快照晚于图片时再补用缓存。

业务状态机、歌词映射测试之外，测试直接编译实际 `ui_action_music_bg.c` 接收部分，模拟 SDK 命令与线程锁；检查重复请求、START 前连续切歌、旧图片丢弃、SDK 续取、投递失败重试和断开。LVGL 测试核对文字补全保留封面及角度、新句柄清理和旧解码结果拒绝。

封面请求和显示已连接到已有 BIP 接收/解码服务；手机必须支持并提供封面。自动测试不等于手机协议互通测试，需要使用固件和对应资源上板验证。

## 封面日志采集

保留从开机、连接手机、开始播放到切换下一首的完整串口日志；每首播放至少 10 秒。同时记录手机型号、系统版本和音乐 App。不要只截取歌曲属性，未出现 BIP 回调也属于定位依据。

- `[PET_MUSIC] cover request`：封面句柄变化后的请求结果，附 `handle`；`ret=0` 表示接受或交给正在运行的 SDK 续取流程，不表示手机已发送图片。命令投递失败时，重复的同句柄属性允许重试。
- `[PET_MUSIC] cover queued by SDK`：当前有未完成的取图请求，此次不再发送命令。
- `[PET_MUSIC] text mode=lyrics`：歌词模式已启用。`lyric source=TITLE` 只在歌词行变化时输出；同句柄的文字补全不应重复出现 `cover request`。
- `[BIP] select` / `receive done`：当前句柄、实际传输句柄和完成图片归属；`state=0` 且 `handle` 与 `wanted` 不同表示快速切歌时主动丢弃旧封面。
- `[BIP] rx`：接收状态、包长度、总长度。状态沿用 SDK：1 开始，2 中间，3 结束，4 错误，5 重复获取，6 上次获取中或无图片。
- `[BIP] duplicate request ignored` / `request pending, keep receiving`：保留传输，不再因状态 5/6 重新收图。
- `[BIP] receive done` / `decode` / `JPEG info`：缓存及解码过程。
- `[BIP] UI notify` / `[PET_MUSIC] cover applied`：投递显示和控件更新；`cover reject` 表示显示层拒绝了图片。
- `[PET_MUSIC] cover buffer`：像素地址、对齐余数及 RGB565 最小/最大值。`align=0` 表示满足绘图对齐，`min=max=0000` 表示整张图像为黑色；设置图片源成功仍需要核对设备实际绘制结果。

封面缓存按至少 32 字节对齐，在启用 PSRAM 的设备上与 demo 一样用 `malloc_psram` 申请，复制后调用 `psram_flush_cache`；无 PSRAM 的构建使用普通堆并调用 `DcuFlushRegion`。独立缓存只申请一次（18432 字节及对齐空间），跨页面重用，避免直接引用 demo 会扩容的缓冲区。`cover buffer` 的 `psram=1` 确认内存类型，`cover applied` 的 `source=1` 确认图片源已设置，均不能代替上板核对画面。

替换图片源前先通过 `lv_image_set_src(..., NULL)` 清理旧源，规避 SDK 的 VARIABLE→BIN 切换把静态描述符当字符串释放的问题；无需改动 SDK 通用图片控件。

封面采用 demo 相同的图片自身圆形裁剪：父容器 `radius=0, clip_corner=false`，图片 `radius=48, clip_corner=true`。父容器圆角原本会把 96×96 图片分别绘入上下两个 ARGB8888 子图层，再遮罩合成；现在直接生成主图层的圆形图片任务。每张封面新增一次 `[PET_MUSIC] cover draw`，`direct=1 radius=48` 表示该路径生效，不等于 GPU 已成功输出像素。

LVGL 联动测试已配置实际 RGB565 帧缓冲，检查封面中心像素、圆角外像素、图片替换及绘制任务没有子图层；电脑软件渲染通过仍需设备 GPU 验证。

歌名在工具使用 `LV_LABEL_LONG_SCROLL_CIRCULAR`：短文字保持静止，超过 288 像素宽度时向左循环滚动；内容相同的状态通知不重复设置文字。

使用工程同一 LVGL/FreeType 和 `lyrics.ttf` 实测：26 号字体行高为 36 像素，“晴天”的排版尺寸为 52×36；原标签高 34 像素会触发垂直循环滚动，即使字形看起来没有越界。标签已调整为 38 像素高，保持与歌词区域分开。

LVGL 联动测试使用同一 TTF，检查短歌名偏移保持为零、长歌名水平偏移递减并循环、刷新通知不中断，以及长歌名切换回短歌名后停止滚动。
