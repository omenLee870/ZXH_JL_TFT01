# H264 软编码器性能文档

> 测试对象：**minih264e v2** 软件 H.264 编码器（模块化重构 + PI32V2 SIMD 汇编优化）
> 测试 demo：`lib/video/minih264/mpi_yuv_h264.c`（直连编码库，不经 MPI；随编码库一起编译，
> 由 app 侧调用 `mpi_yuv_h264_test()`）

---

## 1. 测试目的

为客户提供 BR33 上 H264 软编码在不同**主频 / 内存位置 / 分辨率**下的编码性能（帧率 / 每帧耗时），用于评估编码能力与资源配置。

> 测试结果请直接跳转到 [**§5.1 汇总表**](#5-性能测试结果)。

---

## 2. 固定配置（所有组合均不变）

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 编码器 | minih264e v2 | 模块化重构版 |
| 汇编优化 | **PI32V2_SIMD_EN = 1** | SAD/变换量化/去块滤波等 SIMD 汇编开启 |
| 线程数 | **单线程** | `max_threads = 1`（不分 slice 并行） |
| encode_speed | **9**（`H264E_SPEED_FASTEST`） | 最快档 |
| GOP | **40** | 每 40 帧一个 IDR |
| QP 范围 | **10 ~ 42** | ABR 码控浮动范围 |
| 码率 | **VGA = 1000 kbps；QVGA = 500 kbps** | 随分辨率定 |
| rate control | ABR + `fine_rate_control_flag = 1` | VBV 码控 |
| 输入格式 | NV12 → 就地转 I420 | 转换耗时计入每帧编码时间 |
| fps 口径 | 纯编码耗时 | 仅 `NV12→I420 + H264E_encode`，**不含 SD 卡 IO** |

## 3. 测试变量与组合矩阵

### 3.1 性能配置变量 → 12 组

三个独立配置变量 → **2 × 3 × 2 = 12 组**：

| 变量 | 取值 | 说明 |
|------|------|------|
| 主频 | **320 MHz / 240 MHz** | CPU 主频（320 MHz 需对应 320M 库/时钟配置） |
| 内存位置 | **PSRAM@200MHz / PSRAM@400MHz / SRAM** | 编码器 persist+scratch 及帧缓冲所在内存 |
| 分辨率 | **VGA 640×480 / QVGA 320×240** | 码率相应取 1000 / 500 kbps |

> SRAM（片内 RAM）容量有限，大分辨率放不下。

### 3.2 测试内容场景（每个组合都用同一套场景源测）

同一配置下，编码耗时随**画面复杂度**变化，故每个组合测多类内容、各类取均值，避免单源偶然性：

| 场景类 | 源文件 | 内容 |
|--------|--------|------|
| 室内复杂 | cp1.yuv ~ cp5.yuv | 复杂画面 |
| 室内简单 | ey1.yuv ~ ey5.yuv | 简单画面 |
| 室外 | ot1.yuv ~ ot5.yuv | 室外画面 |

每个分辨率各准备一套上述 3 类共 15 个 NV12 源文件。

## 4. 测试方法

1. **测试源文件**：`storage/sd1/C/nv12/` 下放该分辨率对应的 3 类 15 个 NV12 文件（cp1-5 / ey1-5 / ot1-5）：
   - VGA：640×480，单帧 = `640×480×1.5` = 460800 字节
   - QVGA：320×240，单帧 = `320×240×1.5` = 115200 字节
2. demo 逐个文件执行：`fread` 读 1 帧 NV12 → `NV12→I420` 转换 → `H264E_encode` → `fwrite` 写 .264；**转换耗时计入该帧编码时间**。
3. 每帧用 `timer_get_ms()` 包裹 **转换+编码**，记单帧耗时；每个文件结束打印该文件汇总，全部结束打印全局汇总：
   ```
   [YUV_DEMO] file cp1.yuv: 400 frames, ... avg=...ms min=...ms max=...ms fps=...
   ...
   [YUV_DEMO] Done: 15 files, ... 
   [YUV_DEMO] wallclock avg=...ms min=...ms max=...ms fps=...
   ```
4. **取每个文件的 `fps`**，按 cp/ey/ot 归类，同场景类 5 个文件取均值，填入第 5 节结果表。

> **备注**
> 1. **单线程结果**：本文档所有性能数据均基于 **单线程单核**（`H264E_MAX_THREADS = 1`）测得，多线程多核不在本次测试范围内。
> 2. **VGA + SRAM 不测（#5/#11 标 N/A）**：VGA 编码器内存需求 ≈ persist 1.01MB + scratch 0.71MB ≈ **1.72MB**，超出内部 SRAM 可用容量（`TCFG_MMU_MEMORY_SIZE = 1MB`），放不下。
> 3. **PSRAM 频率无关**：已证 PSRAM@200 vs @400 逐文件 fps/耗时完全一致（#1=#3、#2=#4、#7=#9），软编码为 **CPU 计算瓶颈**。故 400MHz 不再单独测（#10 标 N/A），后续统一按 PSRAM@200 测。320M 软编码吞吐较 240M 提升约 **30%**。
> 4. QVGA + SRAM（#6/#12）编码器 ≈ 0.46MB，可放入内部 SRAM，照常测试。

## 6. 复现步骤（每组配置操作）

每组配置需在**编译/烧录前**按需修改下列位置，然后编译烧录运行 demo，取 5.1 表数据。

| 变量 | 修改位置 | 说明 |
|------|----------|------|
| 分辨率 + 码率 | demo 宏（见下） | `YUV_DEMO_WIDTH/HEIGHT/BITRATE_KBPS` |
| 内存位置 | demo 宏 `DEMO_MALLOC` | PSRAM=`malloc_psram`，SRAM=`malloc` |
| 主频 | 工程/时钟配置 | 320M 需对应 320M 库 + 时钟配置 |
| PSRAM 频率 | PSRAM 初始化/总线时钟配置 | 200/400 MHz |

### demo 侧宏（`lib/video/minih264/mpi_yuv_h264.c`）

```c
#define DEMO_MALLOC(size)  malloc_psram(size)   /* PSRAM: malloc_psram / SRAM: malloc */

#define YUV_DEMO_WIDTH          640             /* VGA=640  QVGA=320 */
#define YUV_DEMO_HEIGHT         480             /* VGA=480  QVGA=240 */
#define YUV_DEMO_GOP            40
#define YUV_DEMO_QP_MIN         10
#define YUV_DEMO_QP_MAX         42
#define YUV_DEMO_BITRATE_KBPS   1000            /* VGA=1000  QVGA=500 */
#define YUV_DEMO_SPEED          9
```

- **VGA**：`WIDTH=640 HEIGHT=480 BITRATE_KBPS=1000`
- **QVGA**：`WIDTH=320 HEIGHT=240 BITRATE_KBPS=500`

> 注意：编码器为 **单线程**（`H264E_MAX_THREADS = 1`），scratch 仅 1 份分配（640×480 编码器内存约 1.72MB，QVGA 约 0.46MB）；若跑 SRAM 需确认容量够。
